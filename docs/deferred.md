# Deferred Items

Everything deliberately left out of Origin 0.1, with the phase it is scheduled against
and why it was deferred. Process rule 4: deferred items are recorded here, never
silently dropped. An item may move phases; it may not vanish without a line in
`docs/phases/N-complete.md` saying so.

## Language

| Item | Why deferred | Phase |
|---|---|---|
| `if let` / `while let` | pure sugar over a two-arm `match`; needs the match lowering first | Phase 3 |
| `?` on `Option[T]` | delivered in Phase 7: no shared "try" abstraction was needed, only a second arm in the one rule -- `?` unwraps `Some` and returns `Option::None` early, exactly as it unwraps `Ok` and returns `Err`. Building it turned up a real bug in the `Result` half: the early return handed back the value it was given, and `Result[i64, E]::Err` and `Result[String, E]::Err` are different layouts (ADR-0019), so a caller's `match` matched no arm. It rebuilds at the enclosing function's own return type now | done |
| Error conversion in `?` via `Into` | needs a blanket-impl story that interacts with coherence (ADR-0011) | Phase 8 |
| Trait objects / `dyn` | needs the uniform value representation monomorphization avoids (ADR-0010) | Phase 7 |
| Multi-parameter traits | inference ambiguity; not needed for the stdlib as designed | Phase 7 |
| Generic associated types | needs higher-kinded machinery | — (not planned) |
| Specialization | interacts badly with coherence; open problem elsewhere | — (not planned) |
| Operator overloading | `+` on user types needs traits in the operator path; `==` is already structural | Phase 7 |
| Index syntax `v[i]` | ADR-0028 closed this rather than doing it: collections are a library, `xs.get(i)` returns `Option[T]` and `xs.at(i)` traps, and neither needs a production ADR-0013 ruled out. Adding `v.[i]` later is additive sugar over the same method call | — (not planned: ADR-0028 decided against it) |
| Collection literals | same ambiguity constraint as index syntax, and the same answer: a list is built by pushing to it (ADR-0028). The reason to revisit is ergonomics -- a test that wants three elements writes three pushes -- rather than capability | Phase 8 |
| Attributes and `derive` | mostly unnecessary because `==` is compiler-generated (ADR-0011) | Phase 7 |
| Range patterns (`1..=9`) | exhaustiveness over integer ranges needs interval splitting in Maranget | Phase 7 |
| Labelled `break` / `continue` | needs loop labels in the resolver | Phase 7 |
| Glob imports, `use ... as` | ambiguity rules and rename bookkeeping | Phase 7 |
| String interpolation | delivered in Phase 7: `"\\(expr)"`, specified in §01 (lexical) and §14 (meaning). No formatting trait was needed in the end -- `Show` already renders a value and `Str::concat` already joins two strings, so the parser desugars a literal into those calls and nothing downstream learns a new form. The escape is where it lives because `\\(` was a rejected escape before this existed, so no literal that used to be valid changes meaning, and there is no `{{` doubling rule | done |
| Raw string literals | trivial, but no consumer yet | Phase 7 |
| `isize` / `usize` | add only if the Mach-O writer needs them in Origin source | Phase 5 |
| Fixed-size arrays `[T; N]` | needs const generics | Phase 7 |
| `const fn` / calls in const initializers | needs the const evaluator to run real code | Phase 5 |
| The never type `!` written in source | exists in the checker, no syntax for it | Phase 7 |
| Associated functions (`Type::new()`) | an `impl` block holds methods, and a path naming one of its functions without a receiver resolves to nothing. It is what a constructor wants to be called, and `spec/13-collections.md` says `list::new` instead. Adding it is resolver work (a `Type::member` path against an impl's items) plus the inference question of where the impl's type arguments come from when no receiver supplies them | Phase 8 |
| Doc comment capture | needed by LSP hover, not before | Phase 8 |
| Effect checking for `match` guards | closes the one "unspecified" clause in the spec (§05) | Phase 5 |
| Cycle detection in structural `==` | a cyclic graph makes `==` diverge (§04) | Phase 7 |
| Tuple element access (`t.0`) | found in Phase 1: the grammar's `.` takes an identifier, so a tuple can only be read by pattern. Needs either integer field syntax or a lexer rule for `.0` | Phase 7 |
| Float formatting in `to_str` | delivered in Phase 8: the shortest decimal that reads back as the same float, specified in `docs/spec/16-floats.md` and written in Origin in the prelude over two compiler-provided operations that reinterpret a float's bits (ADR-0031). Steele & White's free-format conversion in Burger & Dybvig's form, over base-10^9 bignums on the prelude's own `List[i64]`; `tests/floats` holds it to Go's `strconv` over fourteen thousand bit patterns, which is what caught the tie rule (an exact halfway case goes to the *even* digit, not up). The `unimplemented:` in native code is gone | done |
| Unicode identifiers in stage1 | stage1's lexer treats every scalar value at or above U+0080 as an identifier character, where `internal/lex` asks Unicode whether it is a letter. Narrowing it needs the XID_Start and XID_Continue tables, which is a data problem rather than a code one. Every identifier in this repository is ASCII, so the two lexers agree on the corpus `tests/selfhost` runs them over, and where they would not is written down here rather than papered over | Phase 9 |
| Reading a decimal into a float | delivered in Phase 9: `Str::parse_float` is the inverse of spec/16-floats.md's rendering, correctly rounded with ties to even, and written in Origin over the same base-10^9 bignums the renderer uses (ADR-0031). It exists because stage1's lexer has to turn a float literal into a number, and because a language that can print a float and not read one back is missing half of an inverse pair. `tests/floats` holds it to Go's `strconv.ParseFloat` over ~3,700 decimals, which is what caught the rounding bug: the quotient's range has to be checked *before* rounding, or a value one scale short rounds up into range and an answer with a bit missing looks correct | done |
| A fixed virtual-machine heap | found in Phase 9 by running the stage1 lexer over this repository's own source: the VM's old generation was 2 MiB and could not grow, so a program native code runs on its 64 MiB heap trapped with `out of memory`. Growing it turned up the real bug -- a major collection discovered the shortfall *during* its Cheney scan, with some objects moved and some not, set the sticky out-of-memory flag and handed the mutator a reference it had not updated. The destination is sized before the copy now, which a copying collector can always do (the live set cannot exceed the nursery plus the from-space), and the to-space is moved and resized freely because it holds nothing | done |
| A block expression in statement position | found in Phase 9 while writing the lexer in Origin. spec/02-grammar.md's `ExprStmt = ExprWithBlock [ ";" ] \| ExprWithoutBlock ";"` makes a braced expression a complete statement, and the parser carried on into a binary operator instead: `if b > 0 { return 1; }` followed by `-1` read as a subtraction from `()`, and the diagnostic was about the types rather than the shape | done |
| `char::from_u32` | found in Phase 9 while writing a lexer in Origin, and named in two places that were both wrong about it existing: spec/04-expressions.md's cast table and the `E0605` help text for a rejected `u32 as char`. It is an associated item on the primitive, like `i64::MAX`, and so needs no `use` -- which is not a convenience but a requirement, since a `std::char` module shadows the primitive `char` in type position and makes `Option[char]` stop resolving. The compiler provides the predicate and `internal/compile` builds the `Option`, ADR-0025's split unchanged | done |
| Methods on `Option` and `Result` | found in Phase 8 by writing Origin: both were two enum declarations and nothing else, so the only ways to take one apart were `match` and `?` -- and the diagnostic for a `?` with a mismatched error type told the writer to call `.map_err(\|e\| ...)`, which did not exist. `is_some`, `unwrap_or`, `unwrap_or_else`, `expect`, `map`, `and_then`, `filter` and `ok_or` on `Option`; `is_ok`, `is_err`, `ok`, `err`, `unwrap_or`, `expect`, `map`, `map_err` and `and_then` on `Result`. All of it ordinary Origin in the prelude, none of it needing the compiler (ADR-0028). Deliberately no `unwrap()`: `expect(msg)` costs a message and buys a diagnostic worth reading | done |
| A lambda argument's parameter types | found in Phase 8 by writing Origin: §03 already said "lambda parameters may omit theirs when the expected type is known from context", and a call did not supply one -- every argument was inferred before the callee's parameter types were, so a lambda's parameters were fresh variables and a method call in its body had no receiver type to look up. `sort_by(xs, \|a, b\| a < b)` worked only because `<` on two unknowns could wait; anything calling a method needed `\|v: Cell[i64]\|`. Arguments are now checked against the declared parameter types with lambdas last, so the ordinary arguments solve what the lambdas need | done |
| Bounds on an associated type | found in Phase 8 by writing Origin: `type Tag: Show;` is in §02's grammar and the checker kept only the name, so a trait's default body could not call a method the bound promised and an impl could define the associated type as anything at all -- including, for `IntoIterator`, an `Iter` with no `Iterator` impl. Both directions are checked now, and reducing `Self::Tag` to what an instantiation makes it is `check.Resolver.Normalize`, which `internal/compile` asks rather than reimplementing (ADR-0029) | done |
| Assigning a captured binding | found in Phase 8 by writing Origin: §04 said "the lambda cannot reassign the outer binding" and nothing enforced it. The interpreter assigned the lambda's own copy and lost it at the next call (a counter written that way returned the same number every time), and the bytecode compiler stopped with an `unimplemented:` -- one program, two meanings and a build failure. It is now `E0595` in the resolver, which is the only place that knows a name crossed a lambda boundary, and `Cell[T]` is in the prelude so that §04's own advice ("share an aggregate with a `mut` field") names a type that exists | done |
| Float remainder in native code | `%` on floats works in the interpreter and the VM (Go's `math.Mod`) and fails to build natively: SSE has no remainder instruction, x87's `fprem` is the only hardware form, and pulling the x87 stack in for one operation was not worth it in Phase 5. Found while closing Phase 8's float work; it fails loudly at compile time rather than computing something wrong, so no program can depend on it silently. A correct `fmod` is iterative reduction over the exponent difference, which is now writable in Origin the way the decimal rendering is (ADR-0031) | Phase 9 |
| Per-width integer overflow | delivered in Phase 8: `internal/arith` is one definition of integer arithmetic per declared width, carrying `uint64` bit patterns and extending every result the way its kind says. The three engines share it -- the interpreter and the VM by calling it, the backend by mirroring it against the same tests -- so `255u8 + 1` traps and `255u32 + 1` is 256 everywhere, at every optimization level. The width travels with the instruction (`bytecode.Kind`, ADR-0021) because a register holds sixty-four bits and nothing in it says which of the eight integer types they are | done |
| `u64::MAX` at run time | delivered in Phase 8: a value holds the bit pattern and the static type says how to read it, so `u64::MAX` is every bit set and renders as 18446744073709551615. What had to be told the signedness rather than reading it off the value: division, remainder, right shift, `<` and friends, `cmp` (which already had a separate `BuiltinCmpUint` for native code and now uses it in the VM too), and `to_str` in all three engines -- `rt_int_to_str` takes it as an argument | done |
| Exact object layouts from monomorphization | delivered in Phase 5: every struct, tuple, enum-variant and closure instantiation gets its own exact `Fixed` layout, keyed the same way `internal/mono` keys a function instance (ADR-0019). `layout.Tagged` is retired | done |
| `for` loops in compiled code | delivered in Phase 5: `internal/check`'s `forElementType` records the desugaring's two implicit calls (`into_iter()`, `next()`) as instantiations keyed to existing AST nodes (`v.Iter`, `v` itself), so `internal/mono` and `internal/compile`'s `forExpr` find a concrete callee for each exactly as an explicit method call would; the backend needed no changes since a desugared `for` lowers to ops (calls, jumps, `is_variant`, `get_field`) it already handled | done |
| Decision-tree lowering for `match` | the compiler emits a linear chain of arm tests; the tree belongs on the control-flow graph | Phase 5 |
| Instantiation depth diagnostic truncation | E0055's instantiation chain is not shortened past the list level, so a deep chain's note is long: each entry's type name has already grown by the time truncation would apply | Phase 5 |
| Orphan rule (`E0117`) | cannot be violated while a program is one package; it becomes checkable with the package manager | Phase 8 |
| Compiler-provided impls in Origin | `Show`, `Ord` and `Int` for the primitives are registered by the checker because their bodies need operations the language does not expose yet | Phase 7 |
| Static field-mutability check | delivered in Phase 2: assigning a non-`mut` field is now `E0594` at compile time | done |
| Block-level (nested) item declarations | `check/body.go` documents the choice explicitly: "Phase 2 checks items at file level only... left to Phase 8's incremental machinery." A struct declared inside a function body resolves but is never checked, so before Phase 5's exact layouts a use of it silently compiled against whichever descriptor happened to be at index 0; it now fails loudly instead (`internal/compile`'s per-instantiation lookup has nothing to find), which is correct per process rule 8 but not a fix | Phase 8 |

## Runtime

| Item | Why deferred | Phase |
|---|---|---|
| Per-green-thread panic isolation | decided in Phase 6, and still deferred, now with a reason rather than a deadline (ADR-0026): isolation requires a dead thread to leave shared state usable, and under a shared heap (ADR-0008) with `Mutex` as the sharing mechanism (ADR-0014) a thread that panics inside `with` dies holding a lock over a half-mutated value. Rust survives that with unwinding plus poisoning, Erlang by sharing nothing; ADR-0006 ruled out the first and ADR-0008 the second. A surviving thread would read a value satisfying no invariant, which is a wrong answer rather than a crash — so the process dies instead. Reachable only if unwinding ever arrives, and to be revisited in the same breath as ADR-0006 | — (blocked on ADR-0006) |
| Weak references | no consumer; complicates the moving collector | Phase 7 |
| Finalizers | resurrect-and-order problems for no current benefit | Phase 7 |
| Exposed atomics | ADR-0014 made these conditional on the scheduler needing them in Origin source; it does not, since the scheduler is written in Go | — (not planned) |
| `select` over several channels | needs a multi-way blocking primitive and a fairness policy; every program in Phase 6's scope is expressible with one channel per thread or a `Mutex`. Should land as a function over a list of cases, not a control-flow construct, or ADR-0025 is being revisited by accident | Phase 7 |
| Real parallelism in native code | the native scheduler runs one green thread at a time on the one OS thread `_start` was given, for the same reason the virtual machine's does: ADR-0022's collector is stop-the-world and precise, so every thread's stack is a root set and none may be mid-read of an object another is about to move. Preemption at back edges (§08) is implemented and is what stops a compute loop starving a ready thread; what is missing is a second processor, which needs the collector to stop the world across OS threads first | Phase 7 |
| Real parallelism in the virtual machine | the VM owns a precise *moving* collector, so every thread's stack is a root set and no thread may be mid-read of an object another thread's allocation is about to move. Threads therefore interleave: a thread holds one world lock while executing bytecode and releases it at safepoints, which is exactly the scheduling §08 specifies ("preemptive at safepoints") and exactly what makes a collection safe. Parallelism is not promised by the specification, and a program whose output depends on which thread wins a race is not a valid differential case anyway (§12's determinism clause). The interpreter is genuinely parallel because Go's collector finds its values wherever they are | Phase 7 |
| Async I/O | §08 originally scoped "kqueue-backed async I/O" to Phase 6; §12 amends that, because `io::println` is the entire I/O surface and there is nothing to be asynchronous about. Follows the file and socket APIs | Phase 7 |
| Preventing a `Mutex`-protected value from escaping `with` | the closure form releases the lock at a known point, but nothing stops the body returning the protected value and using it unlocked. Closing this needs a lifetime or region system, which ADR-0004 declined for the language as a whole | — (blocked on ADR-0004) |
| Reclaiming a channel, a mutex or a finished thread's stack in native code | each is one anonymous mapping the runtime never unmaps, and a channel's queue keeps its values alive for as long as the program runs. Nothing dangles -- the leak is the whole point of it being safe -- but a program that makes channels in a loop grows without bound. Freeing one needs the runtime to know when the last handle to it is gone, and the handle a program holds is an integer inside a prelude struct rather than a reference the collector can trace | Phase 7 |
| Guard page on a green thread's stack | a thread's 8 MiB stack is a plain mapping, so running off the end faults instead of trapping with §08's `stack overflow`. One `PROT_NONE` page below the mapping turns the fault into a signal the runtime could name -- which needs a signal handler, which needs a fair amount of runtime the phase does not otherwise want | Phase 7 |
| Lock-free data structures in safe Origin | impossible under ADR-0014; would need an `unsafe` escape hatch | — (not planned) |
| `unsafe` blocks | nothing in the design needs one yet; adding one is a spec-pillar change | — (not planned) |

| File I/O | delivered in Phase 7 (spec/15-files.md, ADR-0030): `read_to_string`, `write_string` and `file_exists` in the prelude over four compiler-provided operations. A whole file at a time and no handle, because a handle is a resource Origin cannot close automatically | done |
| Directory listing, metadata, rename, delete, the current directory, streaming reads and writes | spec/15-files.md scoped a compiler's needs: read a source file, write an object file, ask whether a path is there. Each of these is additive -- a new operation beside the four, with the same status-to-`IoError` shape -- and none is needed before something asks for it | Phase 8 |
| The command line and the exit status | delivered in Phase 9 (spec/17-process.md): `args()` in the prelude over `env::arg_count`/`env::arg_at`, and `process::exit`. The compiler contributes three operations and the prelude contributes the `List` and the UTF-8 check, which is ADR-0025's split -- a runtime returns a primitive or a `String`, never a prelude type. In native code the vector is the kernel's own: `_start` saves the address the stack came in at before aligning it away, because there is no libc to have parsed it | done |
| Environment variables, the current directory, spawning a process, and standard input | spec/17-process.md scoped exactly what makes a compiler invocable: which file, and whether it worked. Each of these is additive and none is needed before something asks for it. Standard input is the one with a design question attached -- it is a stream, and §15 has so far avoided handles entirely (ADR-0030) | Phase 10 |
| A `Path` type | a path is a `String` passed to the system unchanged (spec/15-files.md). Joining, normalizing and splitting are string operations until something needs them to be more, and making them more early would mean deciding what a path *is* on two systems that disagree | Phase 8 |

| stage1's name resolution | delivered in Phase 9: `stage1/src/resolve.origin`, a translation of `internal/resolve` -- the module tree, `use` and visibility, the four passes that make module cycles legal, scopes, locals and shadowing, captures, associated-type projections, `break`/`continue` depth and the assignability rules. Held to the Go one over 397 packages and 744,896 trace lines, diagnostics and their wording included. The oracle is the one thing that had to be invented: side tables keyed by node id cannot be compared against a tree that has no node ids, so both sides emit one line per resolution event in order and the *sequence* is what is compared (`internal/resolve/trace.go`) | done |

| stage1's diagnostic wording | delivered in Phase 9: `tests/selfhost` now compares the whole diagnostic line -- file, line, column and message -- for both the parser and the resolver, over the whole corpus. What it took on the parser side was a `token_name` (an identifier by its own text, a literal by its kind, everything else by its spelling), an uppercase hex formatter for the two messages about scalar values, and about a dozen message sites. One divergence is left and is unreachable: `invalid character %q in source` renders the offending scalar the way Go's `%q` does, which no file in the corpus triggers | done |

## Toolchain

| Cross-build instantiation caching | mitigation for monomorphization compile time (ADR-0010) | Phase 8 |

The snapshots shrank by 1546 lines | done |

| Incremental compilation in the LSP | needs the query architecture; full recheck first | Phase 8 |
| Closures in native code | delivered in Phase 5 (ADR-0020): `internal/backend/closures.go`'s `resolveClosureCalls` boxes an escaping bare function reference into the same one-word closure shape `internal/vm/fields.go`'s `boxIfFn` builds dynamically, and repoints a call whose callee is not a bare function value at a new `OpCallClosure`, which passes the closure reference on the stack rather than shifting argument registers | done |

Wiring this up as `Kind`'s first reader immediately found and fixed a real bug: `internal/opt`'s `-O1`/`-O2` path was silently dropping `Kind` on its bytecode round trip (`ir.Emit`'s `OpCall`/`OpGetField`, a fresh `Fn`'s `ParamKinds`/`CaptureKinds`, and inlining's value cloner) | done |
| The stack-map table | delivered in Phase 5 (ADR-0021): `internal/layout/stackmap.go` owns the encoded shape (`StackMapEntry`, `EncodeStackMap`/`LookupStackMap`/`DecodeStackMap`); `regalloc.go`'s `allocate` also computes `callSiteRegs` (which callee-saved registers hold a live reference at each call-clobbering point — never caller-saved, by ADR-0018's own invariant); `internal/backend/stackmap.go`'s `recordCall` is wired into every user-code call site `lower.go` lowers, and `buildStackMap`/`writeStackMapFields` resolve, sort, encode, and poke the table's address and count into the runtime block. Runtime-internal call sites (`write`, `print`, `intToStr`, trap/panic) deliberately get no entry. Verified end to end through the real compiler (`internal/backend/stackmap_test.go`: every entry's return address lands in the text segment, the table is address-sorted, a live reference survives an allocation in a register, the runtime block's count matches). Nothing consumes the table yet | done |
| Native heap collection | delivered in Phase 5 (ADR-0022): a single-space, stop-the-world, semispace-copying collector. `emitAlloc` collects once and retries on an out-of-space bump, trapping `out of memory` only if the retry still does not fit. `rt_collect` walks the `rbp` chain from the immediate caller of `alloc` (`StackMapEntry.SavedMask`, also new, is what lets it recover an outer frame's original callee-saved register values from an inner frame's own save slots as it goes), evacuating every register and stack-slot root via Cheney's algorithm (`rt_evacuate`, `rt_scan_object`), then flips which semispace is current. A frame with no stack-map entry (one of runtime.go's own routines, which allocate internally but were never wired into `recordCall`) gets a synthetic all-saved, no-roots-of-its-own entry rather than being treated as a gap. Verified against the real compiler and a real collection end to end (`tests/e2e/cases/gc_reclaims_discarded_allocations`, spec/10-examples.md #13) and by the full differential suite | done |
| A `-O2` fixed-point non-convergence inside a `while` loop that assigns two loop-carried variables from the loop variable two different ways each iteration (minimally: `a = i; b = i + 1; i = i + 1;` inside `while i < N`, no struct or allocation needed) | a Phase 4 optimizer bug, found while building Phase 5's native collector stress test; root-caused and fixed: `CommonSubexpressions` (`internal/opt/cse.go`) reported `changed` whenever it found a dominating duplicate, even when the duplicate had zero uses left to replace. Fixed by reporting `changed` only when a use was actually replaced, making the pass idempotent. `docs/spec/10-examples.md` #13 still uses `Pair { a: i, b: i }` rather than reverting to `Pair { a: i, b: i + 1 }`, since the simpler form serves its own point just as well; the bug itself is covered directly (`internal/opt/opt_test.go`'s `TestCommonSubexpressionsIsIdempotentOnAnUnusedTrappingDuplicate`) and end to end (`tests/e2e/cases/opt_cse_converges_on_a_trapping_duplicate`) | done |
| Structural `==`/`!=` on aggregates and `String` in native code | delivered in Phase 5: `equal_objects` reads an embedded per-`TypeID` layout table and recurses on a `WordRef` field, mirroring `internal/vm`'s `equalObjects` exactly (`internal/backend/equal.go`) | done |
| Structural `<`/`<=`/`>`/`>=` on `String` in native code | delivered in Phase 5: `compare_bytes` (`internal/backend/equal.go`) does the byte-lexicographic walk `equal_objects`' `ByteArray` case already needed, returning a three-way sign both `stringOrder` and `cmp` (`buildOrdering`) read | done |
| The `cmp` builtin in native code | delivered in Phase 5: rather than widen `OpCallBuiltin` with an operand-kind operand, `compile.cmpBuiltinFor` picks one of four kind-specific builtins (`BuiltinCmpInt`/`Uint`/`Float`/`String`) at compile time, so the backend already knows which comparison a given call needs without reading anything from the instruction beyond which builtin it is | done |
